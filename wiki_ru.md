# Описание компонента zh_avr_touch_pad

## Общие сведения

**zh_avr_touch_pad** — прошивка для AVR-микроконтроллеров ATMega168/328, реализующая беспроводную сенсорную кнопку на базе трансивера nRF24L01+.

Компонент работает в режиме глубокого сна (Power-down), пробуждается по изменению уровня на пине сенсорного датчика (PCINT2) и передаёт на шлюз пакет с идентификатором устройства и уровнем заряда батареи.

### Основные возможности

1. **Сверхнизкое энергопотребление** — около 2 мкА в режиме сна (Power-down).
2. **Передача уровня заряда батареи** — измерение напряжения через внутренний АЦП с опорным напряжением 1,1 В.
3. **Работа по протоколу nRF24L01+** — передача через SPI, адресная доставка на шлюз.
4. **Поддержка ATMega168/328** — все варианты: ATMega168/168P/168PB/328/328P/328PB. Для PB-версий SPI-регистры автоматически маппятся в SPCR0/SPSR0/SPDR0.
5. **Минимальная обвязка** — установка в стандартный корпус сенсорного выключателя.
6. **Пробуждение по PCINT2** — rising edge на пине PD3 (PCINT19).
7. **Автономная работа** — не требует внешних подтягивающих резисторов.
8. **Защита от таймаутов** — watchdog timer для прерывания зависшей передачи.

## Внутреннее устройство

### Структура данных

Компонент не использует динамическое выделение памяти и сложные структуры данных. Все данные передаются как структура `zh_rf_sensor_transmitted_data_t` фиксированной длины из внешней библиотеки `zh_rf_config`. Размер структуры статически проверяется на соответствие максимальному payload nRF24L01+ (32 байта) через `typedef char` assert.

#### Формат передаваемого пакета

Пакет хранится в глобальной переменной `_transmitted_data` типа `zh_rf_sensor_transmitted_data_t` из библиотеки `zh_rf_config`. Перед каждой передачей обновляется только поле `battery_voltage`.

| Поле | Тип | Описание |
| ------ | ----- | ---------- |
| `id` | `int16_t` | Идентификатор устройства (`DEVICE_ID = 6`) |
| `type` | `int16_t` | Тип устройства (`ZH_RF_SENSOR_TOUCH_SWITCH`) |
| `battery_voltage` | `int16_t` | Напряжение батареи × 100 (например, 330 = 3.30 В) |
| `value_1`–`value_4` | `int16_t` | Зарезервированы (равны 0) |

### Конфигурационные макросы

| Макрос | Значение | Описание |
| -------- | ---------- | ---------- |
| `GATEWAY_CHANNEL` | `120` | Радиоканал шлюза (nRF24L01+ RF_CH) |
| `GATEWAY_ADDRESS` | `0xDDEEFF` | 3-байтовый адрес шлюза (TX_ADDR и RX_ADDR_P0) |
| `DEVICE_ID` | `6` | Уникальный идентификатор устройства |
| `BATTERY_VOLTAGE_CALIBRATION` | `1.0f` | Коэффициент калибровки измерения напряжения батареи |

### Назначения пинов

| Пин | Функция |
| ----- | --------- |
| PB1 | CE — управление передачей nRF24L01+ |
| PB2 | CSN — SPI-селект nRF24L01+ |
| PB3 | MOSI — SPI выход |
| PB4 | MISO — SPI вход |
| PB5 | SCK — SPI тактирование |
| PD2 | IRQ — вход прерывания nRF24L01+ (INT0, active low) |
| PD3 | PAD_GPIO_INT — вход сенсорного датчика (PCINT2, rising edge) |

Тип устройства задаётся не макросом, а значением перечисления `ZH_RF_SENSOR_TOUCH_SWITCH` из библиотеки `zh_rf_config`.

### Управление памятью

Компонент не использует динамическую память. Все данные хранятся в статической области. Глобальная переменная `_transmitted_data` инициализируется один раз при старте (идентификатор и тип), в рабочем цикле обновляется только поле `battery_voltage`. Флаги `_send_request`, `_nrf_irq_fired`, `_spi_fault` объявлены как `static volatile bool` для корректного доступа из ISR и главного цикла.

## API (интерфейс)

Все функции являются `static` и доступны только внутри модуля `zh_avr_touch_pad.c`.

### Инициализация

| Функция | Описание |
| --------- | ---------- |
| `_zh_gpio_default_init()` | Инициализация всех GPIO портов (PORTB–PORTE) как входов с подтягивающими резисторами |
| `_zh_pad_interrupt_init()` | Настройка PCINT2 для пробуждения по касанию (PCINT19 на PD3, rising edge) |
| `_zh_spi_init()` | Инициализация аппаратного SPI в режиме мастера (Fosc/16) |
| `_zh_nrf24_init()` | Инициализация трансивера nRF24L01+: настройка адресов, канала, CRC, ретрансмиссий |

### Измерение

| Функция | Описание |
|---------|----------|
| `_zh_get_battery_voltage()` | Измерение напряжения батареи через внутренний АЦП с опорой 1,1 В |

### Передача данных

| Функция | Описание |
|---------|----------|
| `_zh_nrf24_send()` | Передача буфера через nRF24L01+ с полным циклом TX: Power Up, FLUSH_TX, загрузка W_TX_PAYLOAD, импульс CE, ожидание флага TX_DS/MAX_RT по пину IRQ, сброс статуса и переход в Power Down |

### Низкоуровневые SPI-операции

| Функция | Описание |
| --------- | ---------- |
| `_zh_spi_transfer()` | Обмен одного байта по SPI с таймаутом и обработкой ошибок |
| `_zh_nrf24_write_register()` | Запись одного байта в регистр nRF24L01+ |
| `_zh_nrf24_write_buff_register()` | Запись многобайтового буфера в регистр nRF24L01+ |
| `_zh_nrf24_write_buffer()` | Запись буфера данных с указанной командой |
| `_zh_nrf24_send_command()` | Отправка однобайтовой команды и чтение статуса |

### Таймауты

| Функция | Описание |
|---------|----------|
| `_zh_wdt_timeout_start()` | Запуск watchdog timer (WDIE, WDP1\|WDP0 — ~85 мс) для защиты от зависшей передачи |
| `_zh_wdt_timeout_stop()` | Остановка watchdog timer |

## Прерывания

### ISR(PCINT2_vect) — пробуждение по касанию

Устанавливает `_send_request = true` и отключает сон при изменении уровня на пине PD3 (сенсорный датчик) на высокий.

### ISR(INT0_vect) — завершение передачи nRF24L01+

Отключает INT0, устанавливает `_nrf_irq_fired = true` и отключает сон после успешной передачи.

### ISR(WDT_vect) — таймаут передачи

Отключает watchdog, устанавливает `_nrf_irq_fired = true` для прерывания ожидания передачи при таймауте.

---

## Потокобезопасность

Компонент работает на bare-metal AVR без RTOS. Синхронизация между прерываниями и главным циклом реализуется следующим образом:

1. **`volatile` флаг** — переменная `_send_request` объявлена как `static volatile bool`, что гарантирует чтение актуального значения из памяти при каждой проверке в главном цикле.
2. **Атомарная запись из ISR** — обработка PCINT2 устанавливает флаг в единицу. Запись одного байта на AVR является атомарной операцией.
3. **Отключение прерываний при инициализации** — `cli()` перед настройкой периферии исключает гонки при старте.
4. **Флаг ошибки SPI** — `_spi_fault` отслеживает ошибки SPI-коммуникации во время передачи, передаваемые по цепочке вызовов.

## Алгоритмы

### Алгоритм измерения напряжения батареи

- ADC конфигурируется с внутренним опорным напряжением 1,1 В на канале внутреннего источника 1,1 В (`REFS0=1`, `MUX[3:1]=111`), вход AVcc сравнивается с опорой.
- Предделитель частоты: 128 (ADPS[2:0] = 111), что даёт ~62,5 кГц при 8 МГц.
- Выполняются **две последовательные конверсии**: первая стабилизирует выборку, вторая даёт результат.
- Формула расчёта: `Vbat = (1024.0 × 1.1) / adc_value × BATTERY_VOLTAGE_CALIBRATION`.
- При нулевой выборке (`adc == 0`) возвращается 0.0.
- После измерения АЦП отключается сбросом бита `ADEN` и включением PRADC.

### Алгоритм передачи через nRF24L01+

- Переход в Power Up (бит `PWR_UP` в CONFIG).
- Ожидание 5 мс (время стартования осциллятора).
- Очистка TX FIFO командой `FLUSH_TX`.
- Загрузка полезной нагрузки командой `W_TX_PAYLOAD`.
- Сброс флагов статуса (RX_DR, TX_DS, MAX_RT).
- Если ошибок SPI нет: отключение INT0, очистка INTF0, включение INT0, запуск watchdog, переход в Idle, импульс CE.
- Ожидание завершения по пину IRQ (PD2, INT0) с таймаутом watchdog.
- Сброс флагов статуса, очистка FIFO, переход в Power Down.
- SPI-ошибки на любом этапе прерывают передачу.

### Алгоритм сна и пробуждения

- Главный цикл проверяет флаг `_send_request`.
- Если флаг не установлен — вызывается `sleep_cpu()` (режим Power-down).
- Пробуждение происходит по аппаратному прерыванию PCINT2 (rising edge на PD3).
- ISR устанавливает `_send_request = true`, цикл просыпается и выполняет передачу.
- Во время передачи устройство переходит в Idle-режим, ожидая IRQ от nRF24L01+.

## Примеры использования

### Изменение конфигурации под другое устройство

```c
// Измените идентификатор для нового устройства
#define DEVICE_ID 7       // Уникальный ID в сети
#define BATTERY_VOLTAGE_CALIBRATION 1.05f  // Калибровка АЦП
#define GATEWAY_CHANNEL 120
#define GATEWAY_ADDRESS 0xDDEEFF
```

### Подключение по SPI (схема выводов)

```c
// Назначение пинов AVR для nRF24L01+:
// PB2 (SS)   -> CSN (управление SPI-селектом)
// PB3 (MOSI) -> MOSI
// PB4 (MISO) -> MISO
// PB5 (SCK)  -> SCK
// PB1        -> CE  (управление передачей)
// PD2        -> IRQ (вход INT0, активный низкий, с подтяжкой к VCC)
// PD3        -> PCINT2 (вход сенсорного датчика, rising edge)
```

## Ошибки

Компонент не возвращает коды ошибок. Все функции имеют тип `void` или возвращают однобайтовый статус SPI (`uint8_t`) для низкоуровневых операций.

| Условие | Поведение |
| --------- | ---------- |
| Нулевое показание АЦП | `_zh_get_battery_voltage()` возвращает 0.0 |
| Превышение таймаута SPI-передачи | `_zh_spi_transfer()` возвращает 0xFF, устанавливается `_spi_fault`, передача прерывается |
| Превышение таймаута передачи (WDT) | ISR(WDT_vect) сбрасывает `_nrf_irq_fired`, передача прерывается |
| Неверный аргумент | Не применимо — все функции `static`, аргументы не валидируются |

## Ограничения

1. **Только передача (TX-only)** — компонент не принимает данные, шлюз не может отправить подтверждение на уровне приложения.
2. **Отсутствие шифрования** — CRC включён, но AES-шифрование не используется. Пакеты могут быть перехвачены.
3. **Жёстко зашитый адрес шлюза** — смена адреса требует перепрошивки.
4. **Таймаут передачи** — если шлюз недоступен, пакет теряется. Аппаратные ретрансмиты настроены через `SETUP_RETR = 0xFF` (15 попыток с максимальным интервалом), watchdog таймаут — ~85 мс.
5. **Одно сенсорное событие за цикл** — несколько касаний во время передачи будут потеряны (флаг — один бит).
6. **Точность измерения батареи** — зависит от стабильности внутреннего опорного напряжения 1,1 В и может отличаться от реального напряжения на ±3%.
7. **Поддержка ATMega168/328** — все варианты (168/168P/168PB/328/328P/328PB). Для PB-версий SPI-регистры автоматически маппятся через `#ifndef` макросы.

## Требования для сборки

- PlatformIO с плагином `platform-atmelavr`
- AVR-GCC (входит в состав PlatformIO)
- Библиотека `zh_rf_config` (подключается через `lib_deps` в `platformio.ini`)
- Программатор USBasp (или совместимый)
- Фьюзы: LFUSE=`0xE2`, HFUSE=`0xDF`, EFUSE=`0x07` (8 МГц, без делителя)

## Установка

### Сборка и прошивка через PlatformIO

```bash
pio run -e ATmega328P -t upload
```

### Подключение в проекте

Компонент является самодостаточной прошивкой — не подключается как библиотека. Для интеграции в другой проект скопируйте `src/zh_avr_touch_pad.c`, добавьте зависимость `zh_rf_config` и адаптируйте макросы конфигурации.

```ini
; platformio.ini
lib_deps =
    https://github.com/aZholtikov/zh_rf_config
```

```c
// Зависимости: стандартные заголовки AVR-libc и конфигурация протокола
#include "avr/io.h"
#include "avr/sleep.h"
#include "avr/fuse.h"
#include "avr/interrupt.h"
#include "avr/wdt.h"
#include "util/delay.h"
#include "math.h"
#include "stdbool.h"
#include "zh_rf_config.h"
```
